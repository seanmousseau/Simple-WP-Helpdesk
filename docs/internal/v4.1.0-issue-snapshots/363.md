# REST API v1: replies endpoints (swh/v1/tickets/{id}/replies)

> Source: GitHub issue [#363](https://github.com/seanmousseau/Simple-WP-Helpdesk/issues/363) — snapshot captured 2026-05-27.

Nested resource for ticket replies (comments of type `helpdesk_reply`).

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/tickets/{id}/replies` | List replies for a ticket |
| POST | `/tickets/{id}/replies` | Add a reply |

## Payload

- Request: `{ body, is_internal_note (bool, staff only), attachments (array of media IDs) }`
- Response: reply object with `id, body, author_type (staff/client), is_internal_note, created_at, attachments`

## Behaviour

- Internal notes require `edit_posts` + API key write scope; client-scope keys get 403
- Staff reply triggers the same email + `_swh_unread` handling as the admin UI
- Attachments reuse existing upload validation (mime, size, path-under-uploads check)
- Internal notes excluded from `GET` responses when called with a client-scope key

## Acceptance criteria

- Reply creation fires `swh_ticket_replied` (from hooks issue)
- XSS escaping on `body` via `wp_kses_post`
- Playwright coverage for staff vs client-scope key behaviour
