# REST API v1: tickets CRUD endpoints (swh/v1/tickets)

> Source: GitHub issue [#362](https://github.com/seanmousseau/Simple-WP-Helpdesk/issues/362) — snapshot captured 2026-05-27.

Register the core ticket resource under `swh/v1/tickets`.

## Endpoints

| Method | Path | Purpose | Min capability |
|---|---|---|---|
| GET | `/tickets` | List with filters | `edit_posts` or API key `read` |
| GET | `/tickets/{id}` | Single ticket | same |
| POST | `/tickets` | Create | `edit_posts` or API key `write` |
| PATCH | `/tickets/{id}` | Update status, priority, assignee, category | same |

## List filters

- `status` (array), `priority`, `assignee`, `category` (term id)
- `after`, `before` (ISO-8601 date)
- `search` (matches subject + body)
- `page`, `per_page` (default 20, max 100)
- Pagination headers: `X-WP-Total`, `X-WP-TotalPages`

## Payload shape

Mirror the internal ticket structure (id, subject, status, priority, assignee, requester email, category, SLA status, created_at, updated_at, first_response_at, csat). Full schema goes in the OpenAPI spec issue.

## Writes route through existing handlers

Create/update must call `swh_save_ticket_data()`-equivalent helpers so sanitization, email side effects, and assignment rules stay centralized. Do NOT duplicate save logic in the REST controller.

## Acceptance criteria

- All endpoints return WP_REST_Response with proper status codes (201 create, 200 update, 404 missing)
- Capability check per route via `permission_callback`
- Playwright section covers auth + CRUD + filtering + pagination
- PHPStan level 9 clean
