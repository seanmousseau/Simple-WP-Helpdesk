# [Docs] extended-test-plan.md 5.2 — update expectation to reflect v4.0+ default-view snap-back

> Source: GitHub issue [#504](https://github.com/seanmousseau/Simple-WP-Helpdesk/issues/504) — snapshot captured 2026-05-27.

## Discovered

During the v4.0.7 extended-test run (PR #503 sign-off comment), section 5.2 ("Filters apply via URL hash and persist") failed against current behavior:

- **Runbook says:** filter persists after reload; URL hash contains \`status=open\`.
- **Actual v4.0+ behavior:** clicking a saved view sets the active view client-side but the URL does not change. After reload the view snaps back to "All" by design — that's the same v4.0.0 default-view fix that section 5.1 explicitly tests for ("Both default to the documented 'All' view (NOT 'Unassigned' — that v4.0.0 default regression must not return)").

The two sections contradict each other. The 5.1 fix won.

## Why this matters

Today the runbook is internally inconsistent and a future RC operator following section 5.2 will record a FAIL for behavior that's actually intended. The v4.0.7 sign-off documented it as drift rather than a regression.

## Fix

Update 5.2 to one of:

1. **Drop URL-hash persistence expectation** and verify only that the view label changes client-side when clicked + the table refreshes to filtered rows. Note that reload snapping back to "All" is intentional per the 5.1 default-view contract.
2. **Re-introduce URL-hash filter persistence** as an actual feature on the v4.x roadmap (would supersede part of 5.1).

#1 is the cheap option and matches current behavior. #2 is a real feature decision that needs separate scoping.

## Severity

Low — this is documentation drift only; no end-user impact.
