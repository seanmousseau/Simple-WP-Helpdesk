# Per-key rate limiting (60/min default, configurable override)

> Source: GitHub issue [#367](https://github.com/seanmousseau/Simple-WP-Helpdesk/issues/367) — snapshot captured 2026-05-27.

Extend existing `swh_check_rate_limit()` pattern to REST routes, keyed by API key id (or IP for unauthenticated routes).

## Limits

- Default: 60 requests per rolling 60s
- Per-key override set in key management UI (e.g., 600/min for trusted CI integrations)
- Public `/settings/public` endpoint: 20/min per IP

## Headers

Always emit:
- `X-RateLimit-Limit: 60`
- `X-RateLimit-Remaining: 47`
- `X-RateLimit-Reset: 1704067200` (unix ts)

Over limit → 429 with `Retry-After` header + JSON `{ code: 'swh_rest_rate_limited' }`

## Storage

Transients keyed `swh_rl_api_<key_id>` / `swh_rl_ip_<hash>` — reuse current TTL approach. Fall back to wp_options when persistent cache is absent (already handled in `_clear_rate_limits()` test helper).

## Acceptance criteria

- Playwright hits endpoint in a loop, confirms 429 and headers
- Reset header monotonically decreases until rollover
