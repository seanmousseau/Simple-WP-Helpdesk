# Per-endpoint capability checks + permission_callback wiring

> Source: GitHub issue [#366](https://github.com/seanmousseau/Simple-WP-Helpdesk/issues/366) — snapshot captured 2026-05-27.

Every REST route must have a `permission_callback` — no open endpoints.

## Capability matrix

| Route | WP user check | API key scope |
|---|---|---|
| `GET /tickets*`, `GET /replies*` | `edit_posts` | `read` |
| `POST /tickets`, `PATCH /tickets/*`, `POST /replies` | `edit_posts` | `write` |
| `GET /users/technicians`, `GET /categories` | `edit_posts` | `read` |
| `GET /settings/public` | public (no auth) | n/a |

## Rules

- Staff-level endpoints reject client-scope keys with 403
- Missing / malformed Authorization header → 401 with `{ code: 'swh_rest_auth_required' }`
- Invalid or revoked key → 401 with `{ code: 'swh_rest_auth_invalid' }`
- Scope mismatch → 403 with `{ code: 'swh_rest_scope_insufficient' }`

## Acceptance criteria

- One helper `swh_rest_require( $scope )` usable as permission_callback across routes
- PHPUnit covers each error case
- `hash_equals` / `password_verify` used, never `==`
