# API key management UI (scoped keys, per-key rate limit, revocable)

> Source: GitHub issue [#365](https://github.com/seanmousseau/Simple-WP-Helpdesk/issues/365) — snapshot captured 2026-05-27.

New Settings → Integrations tab for issuing and managing API keys.

## UI

- Table of existing keys: label, scope (read / read+write), last-used date, rate limit override, revoke button
- "Generate new key" form: label, scope, optional rate limit override
- After creation, key shown **once** in a modal with "Copy" button — never retrievable again (only the hash is stored)
- Confirm-before-revoke modal

## Storage

- Key entity: `{ id (uuid), label, scope, hash (password_hash), prefix (first 8 chars for display), created_at, last_used_at, rate_limit, revoked_at }`
- Stored in custom option `swh_api_keys` (array) — fits v4.0 structured options shape
- Never store plaintext key

## Auth flow

- Client sends `Authorization: Bearer swh_<key>`
- Lookup by prefix, verify with `password_verify()`, check scope matches route requirement, check `revoked_at` null
- Update `last_used_at` on success (rate-limited to once per 5 min to avoid write amplification)

## Prefer WP Application Passwords for user-scoped access

Document that Application Passwords (built into WP 5.6+) should be used for user-authenticated API access. Custom keys are for service-to-service integrations where no WP user is appropriate.

## Acceptance criteria

- Revoked keys fail auth immediately
- PHPCS + PHPStan clean
- Playwright section: create key → use it → revoke → verify 401
